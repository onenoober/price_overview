# 系统架构约束

## 架构目标

系统架构必须支持两个人并行开发，并保证解析链路、核价链路、核对链路可以通过数据契约独立联调。

第一版建议按模块化单体或前后端分离单体实现。除非已有明确部署要求，不拆成多个微服务。

## 模块分层

```text
前端页面层
  - 报价任务列表
  - 文件上传页面
  - 解析结果页面
  - 核对与修改页面
  - 报价导出页面

接口层
  - 任务 API
  - 文件 API
  - 解析 API
  - 核价 API
  - 核对 API
  - 导出 API
  - 字典与规则 API

应用服务层
  - QuoteTaskService
  - FileService
  - PdfParseService
  - StepParseService
  - PartFeatureService
  - ProcessRecognitionService
  - QuantityCalculationService
  - PriceRuleService
  - QuoteCalculationService
  - ReviewService
  - ExportService

领域规则层
  - 材料归一规则
  - 表面处理归一规则
  - 工序触发规则
  - 工序冲突消解规则
  - 工程量计算规则
  - 价格匹配规则
  - 风险标记规则

数据层
  - 业务表
  - 字典表
  - 规则表
  - 文件存储
  - 历史样本
  - 审计日志
```

## 模块依赖方向

允许依赖：

```text
页面 -> API -> 应用服务 -> 领域规则 -> 数据层
```

禁止依赖：

| 禁止项 | 说明 |
|---|---|
| 页面直接访问数据库 | 所有数据读写必须通过 API 或服务层。 |
| AI 结果直接写入最终报价 | AI 只能生成候选结果、解释和风险提示。 |
| 价格计算依赖前端字段临时拼接 | 价格计算必须在后端使用结构化数据完成。 |
| 工程量计算读取页面状态 | 工程量必须来自 `part_feature` 和工序结果。 |
| 解析模块直接修改最终报价 | 解析模块只输出特征和风险，不负责报价。 |

## 主要模块边界

| 模块 | 输入 | 输出 | 主责 |
|---|---|---|---|
| 文件管理 | 上传文件、任务 ID | `part_file` | B |
| PDF 解析 | PDF 文件 | `pdf_extract_result` | B |
| STEP 解析 | STEP 文件 | `step_feature_result` | B |
| 特征融合 | PDF 结果、STEP 结果、字典 | `part_feature` | A/B 共同，A 负责结构，B 负责解析适配 |
| 工序识别 | `part_feature`、工序规则 | `process_route` | A |
| 工程量计算 | `part_feature`、`process_route` | `engineering_quantity` | A |
| 价格规则 | 字典、价格表、规则版本 | `price_rule` | A |
| 报价计算 | 工程量、价格规则、风险 | `quote_result` | A |
| 最终核对 | `quote_result`、用户修改 | `human_override`、最终确认价 | B/A 共同，B 页面，A 保存与校验 |
| 报价输出 | 确认结果 | 导出文件、导出记录 | B |

## 数据状态流转

`quote_task.status` 必须使用有限状态，不得用自由文本。

| 状态 | 进入条件 | 允许操作 |
|---|---|---|
| `draft` | 创建任务后 | 上传文件、编辑基本信息、作废 |
| `uploaded` | 至少一个文件上传成功 | 继续上传、启动解析、作废 |
| `parsed` | PDF 或 STEP 至少一个解析完成 | 特征融合、查看解析结果、重新解析 |
| `priced` | 已生成初始报价 | 查看报价、人工核对、重新计算 |
| `pending_review` | 存在必确认风险或人工待确认项 | 修改工序、修改价格、填写原因、确认风险 |
| `confirmed` | 人工确认完成 | 导出、查看历史、作废 |
| `voided` | 用户作废 | 只读 |

## 价格版本原则

每次生成初始报价必须固化价格版本：

| 字段 | 要求 |
|---|---|
| 价格规则版本 | 保存到报价结果。 |
| 取价日期 | 保存到报价结果。 |
| 价格来源 | 每个报价项保存来源。 |
| 计算公式 | 每个报价项保存公式或规则编码。 |
| 人工修改 | 修改后不得覆盖系统初始值。 |

## 风险处理原则

风险项不得只作为前端提示存在，必须进入结构化数据。

风险项至少包含：

| 字段 | 要求 |
|---|---|
| `code` | 稳定风险编码。 |
| `level` | `info`、`warning`、`blocking`。 |
| `message` | 展示给用户的中文说明。 |
| `source` | 来源模块。 |
| `requires_review` | 是否要求人工确认。 |
| `evidence` | 原始证据或计算依据。 |

## AI 调用边界

允许 AI 做：

| 场景 | 输出 |
|---|---|
| PDF 字段抽取辅助 | 候选字段、原文证据、置信度。 |
| 文本归一 | 标准材料、标准表面处理、风险标签候选。 |
| 工序解释 | 对规则命中的自然语言解释。 |
| 异常提示 | 复核建议和风险说明。 |

禁止 AI 做：

| 禁止项 | 说明 |
|---|---|
| 直接写最终报价 | 最终价必须人工确认。 |
| 覆盖价格规则 | 价格规则变更必须走维护和审核。 |
| 无证据生成关键字段 | 材料、热处理、表面处理等必须保存来源。 |
| 绕过待确认状态 | 存在必确认风险时不得直接进入 `confirmed`。 |
