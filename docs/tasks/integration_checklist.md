# 联调检查清单

## 联调目标

验证 A 的核价核心和 B 的解析页面可以通过稳定契约完成闭环。

主链路：

```text
上传文件
-> 解析 PDF/STEP
-> 生成 part_feature
-> 识别 process_route
-> 计算 quantity_result
-> 生成 quote_result
-> 页面核对
-> 人工修改
-> 最终确认
-> 导出
```

## 联调前置条件

| 条件 | 标准 |
|---|---|
| 代码 | A/B 分支均已合并到 `develop` 或联调分支。 |
| 数据库 | 迁移已执行。 |
| 字典 | 材料、工序、表面处理、风险、单位字典已初始化。 |
| 价格 | 至少有 SKD11、S45C、SUS304、AL6061 和核心工序价格。 |
| 样本 | 至少 5 个黄金样本、3 个边界样本。 |
| Schema | 四个核心 Schema 可用于校验。 |

## 样本准备

每个样本必须包含：

| 字段 | 要求 |
|---|---|
| `sample_id` | 唯一。 |
| `pdf_file` | 可为空，但为空时必须测试缺 PDF 风险。 |
| `step_file` | 可为空，但为空时必须测试缺 STEP 风险。 |
| `expected_required_operations` | 必选工序列表。 |
| `expected_risk_codes` | 应出现风险编码。 |
| `reference_quote_amount` | 参考报价，可为空。 |
| `notes` | 人工说明。 |

## 步骤 1：文件上传

检查：

| 检查项 | 通过标准 |
|---|---|
| 创建任务 | 返回 `task_id`，状态为 `draft`。 |
| 上传 PDF | 生成 `part_file`，类型为 `pdf`。 |
| 上传 STEP | 生成 `part_file`，类型为 `step`。 |
| 任务状态 | 上传后进入 `uploaded`。 |
| 缺文件 | 允许继续，但风险可追踪。 |

## 步骤 2：解析与特征融合

检查：

| 检查项 | 通过标准 |
|---|---|
| PDF 结果 | 关键字段有原文、来源、置信度。 |
| STEP 结果 | 尺寸、体积、表面积、孔特征可用。 |
| `part_feature` | 通过 Schema 校验。 |
| 材料归一 | 标准编码正确或标记未知。 |
| 重量校验 | 偏差超过 15% 生成风险。 |
| 缺文件风险 | 缺 PDF/STEP 时风险编码正确。 |

## 步骤 3：工序识别

检查：

| 检查项 | 通过标准 |
|---|---|
| `process_route` | 通过 Schema 校验。 |
| 工序排序 | 顺序稳定。 |
| 必选工序 | 命中样本预期必选工序。 |
| 触发原因 | 每个工序都有原因。 |
| 置信度 | 每个工序有 0-1 数值。 |
| 待确认 | 高风险或低置信度工序标记。 |

## 步骤 4：工程量计算

检查：

| 检查项 | 通过标准 |
|---|---|
| `quantity_result` | 通过 Schema 校验。 |
| 单位 | 每项工程量有单位。 |
| 公式 | 每项工程量有公式。 |
| 依据 | 每项工程量有计算依据。 |
| 无法计算 | 生成风险，不填虚假 0。 |

## 步骤 5：报价计算

检查：

| 检查项 | 通过标准 |
|---|---|
| `quote_result` | 通过 Schema 校验。 |
| 价格版本 | 保存价格版本和取价日期。 |
| 报价明细 | 每项有数量、单价、金额、来源、公式。 |
| 汇总 | 材料费、加工费、表面处理费、管理费、税金、总价。 |
| 风险 | 价格缺失、价格异常可结构化展示。 |
| 状态 | 有必确认风险时为 `pending_review`。 |

## 步骤 6：页面核对

检查：

| 检查项 | 通过标准 |
|---|---|
| 零件特征展示 | 字段与 `part_feature` 一致。 |
| 工序展示 | 字段与 `process_route` 一致。 |
| 工程量展示 | 字段与 `quantity_result` 一致。 |
| 报价展示 | 字段与 `quote_result` 一致。 |
| 风险展示 | 风险等级和必确认状态清楚。 |
| 错误状态 | 解析或核价失败有提示。 |

## 步骤 7：人工修改

检查：

| 检查项 | 通过标准 |
|---|---|
| 修改工序 | 可新增、删除、调整顺序。 |
| 修改价格 | 可修改单价、金额、最终价。 |
| 修改原因 | 必填。 |
| 修改记录 | 进入 `human_override`。 |
| 初始报价 | 原始系统结果保留。 |

## 步骤 8：确认与导出

检查：

| 检查项 | 通过标准 |
|---|---|
| 风险确认 | blocking 风险未确认不得确认报价。 |
| 最终确认 | 状态进入 `confirmed`。 |
| 导出明细 | 包含初始报价、最终报价、修改记录。 |
| 历史样本 | 保存本次输入和结果。 |

## 联调问题分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 主链路无法跑通、数据丢失、错误报价。 | 立即修复。 |
| P1 | 核心指标失败、风险漏报、修改无留痕。 | 当前阶段修复。 |
| P2 | 页面展示问题、非核心字段缺失。 | 进入修复队列。 |
| P3 | 优化项。 | 后续处理。 |

## 联调完成标准

首次联调完成：

- 5-10 个黄金样本主链路跑通。
- 所有 P0 修复。
- P1 有明确负责人和 Issue。
- 四个核心契约均通过 Schema 校验。

正式验收联调完成：

- 黄金样本 30-50 个全部通过。
- 边界样本 20-30 个按预期触发风险。
- 验收指标达到 `docs/06_testing_and_acceptance.md` 标准。
