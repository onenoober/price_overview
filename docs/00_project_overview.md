# 工件核价系统开发总览

## 开发目标

第一版系统必须完成从 PDF 图纸和 STEP 模型输入，到系统初始报价、人工核对、最终确认、历史留痕的完整闭环。

核心目标：

| 目标 | 开发要求 |
|---|---|
| 先出价后调整 | 系统必须先生成可查看、可调整的初始报价。 |
| 规则主导 | 工序识别、工程量计算、价格计算必须以确定性规则和价格库为主。 |
| AI 辅助 | AI 只用于字段抽取、文本归一、解释说明、异常提示，不得直接决定最终价格。 |
| 全程留痕 | 初始报价、人工修改、最终报价、修改原因必须保存。 |
| 可解释 | 每个工序、工程量和报价项必须能说明来源、触发原因和计算依据。 |
| 可联调 | 文件解析、特征融合、工序识别、核价计算、核对页面之间必须通过稳定数据契约衔接。 |

## 第一版范围

第一版只覆盖以下范围：

| 类型 | 范围 |
|---|---|
| 零件类型 | 精密小件、薄片件、板件、简单块件、异形小件。 |
| 材料 | SKD11、S45C、SUS304、AL6061、常见模具钢。 |
| 输入文件 | PDF 图纸、STEP 三维模型、关联附件。 |
| 工序 | 备料、下料、CNC、钻孔、沉孔、攻牙、精孔、线切割、磨削、热处理、化学镀、去毛刺、检验、包装。 |
| 定价 | 单件打样、小批量报价、制造中心内部价格规则。 |
| 输出 | 初始报价、工艺路线、价格明细、风险提示、人工确认结果、修改记录。 |

## 第一版不做

以下内容不得作为第一版开发目标：

| 不做内容 | 处理要求 |
|---|---|
| 轴类件、复杂曲面件、焊接件、装配件自动核价 | 可以识别并提示转人工，不实现自动核价。 |
| 大批量产线报价、长期协议价 | 进入人工报价流程。 |
| 自动网络抓价 | 只保留价格来源字段，不接入自动抓价。 |
| AI 自动决定最终报价 | 禁止。最终报价必须人工确认。 |
| AI 自动覆盖价格库 | 禁止。价格变更必须由价格管理员审核。 |
| 无确认直接生成对外正式报价单 | 第一版只输出内部初始报价和确认结果。 |

## 核心业务链路

```text
创建报价任务
-> 上传 PDF / STEP
-> PDF 字段抽取
-> STEP 几何解析
-> 零件特征融合
-> 工序识别
-> 工程量计算
-> 价格规则匹配
-> 初始报价生成
-> 风险提示与人工核对
-> 人工修改并填写原因
-> 最终确认报价
-> 导出明细
-> 保存历史样本
```

## 开发约束

所有开发必须遵守：

| 约束 | 要求 |
|---|---|
| 数据契约优先 | 变更核心数据结构前必须先更新文档和 Schema。 |
| 小步提交 | 每个 PR 只完成一个明确任务。 |
| 不跨界改动 | 开发者不得在无必要时修改对方主责模块。 |
| 可测试 | 新增规则、计算、接口、页面状态必须有可验证用例。 |
| 可回归 | 黄金样本和边界样本必须能重复运行。 |
| 可追溯 | 报价相关结果必须保存来源、版本、计算依据。 |
