# 历史样本与分析模块

## 模块目标

保存每次报价的输入、系统初始报价、人工修改、最终确认结果和成交信息，为后续规则优化、价格校准和偏差分析提供数据基础。

## 主责

开发者 A 主责数据闭环和分析基础，开发者 B 负责必要的页面展示。

## 输入

| 输入 | 说明 |
|---|---|
| `quote_task` | 报价任务。 |
| `part_feature` | 零件特征快照。 |
| `process_route` | 工序路线快照。 |
| `quantity_result` | 工程量快照。 |
| `quote_result` | 报价结果。 |
| `human_override` | 人工修改记录。 |
| 成交信息 | 可选，后续录入。 |

## 输出

| 输出 | 说明 |
|---|---|
| `quote_history_sample` | 历史样本。 |
| 修改分析数据 | 高频新增工序、删除工序、改价原因。 |
| 价格偏差数据 | 初始价、确认价、成交价差异。 |
| 规则优化建议清单 | 规则漏判、误判、价格偏差。 |

## 样本保存时机

| 时机 | 动作 |
|---|---|
| 生成初始报价 | 保存系统初始结果快照。 |
| 人工修改 | 追加修改记录。 |
| 最终确认 | 保存最终确认结果。 |
| 成交结果录入 | 更新成交价和成交状态。 |
| 作废 | 保留作废原因和已有过程。 |

## 历史样本字段

| 字段 | 说明 |
|---|---|
| `sample_id` | 样本 ID。 |
| `task_id` | 报价任务 ID。 |
| `part_feature_snapshot` | 零件特征快照。 |
| `process_route_snapshot` | 工序路线快照。 |
| `quantity_result_snapshot` | 工程量快照。 |
| `initial_quote_snapshot` | 初始报价快照。 |
| `manual_overrides` | 人工修改记录。 |
| `final_quote_snapshot` | 最终确认报价快照。 |
| `deal_amount` | 成交价，可为空。 |
| `deal_status` | 成交状态。 |
| `created_at` | 创建时间。 |

## 分析口径

| 分析项 | 口径 |
|---|---|
| 高频新增工序 | 人工新增工序次数 / 样本数。 |
| 高频删除工序 | 人工删除工序次数 / 样本数。 |
| 改价偏差 | 最终确认价 - 系统初始报价。 |
| 成交偏差 | 成交价 - 最终确认价。 |
| 规则漏判 | 人工新增且应由规则自动识别的工序。 |
| 规则误判 | 人工删除且不应自动识别的工序。 |

## 不做什么

- 第一版不自动根据历史样本修改规则。
- 第一版不自动根据历史样本覆盖价格。
- 第一版不做复杂预测模型。
- 第一版只提供后续优化的数据基础。

## 验收标准

- 每次确认报价后生成历史样本。
- 初始报价和最终报价可对比。
- 人工修改原因完整。
- 历史样本不因后续规则变化而改变。

## AI Coding 注意事项

- 不要只保存当前最新结果，必须保存快照。
- 不要让历史分析自动改价格规则。
- 不要删除作废任务的历史过程。
- 不要把成交价作为自动报价的直接替代值。
