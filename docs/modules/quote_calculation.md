# 核价计算模块

## 模块目标

根据工程量、价格规则、风险附加和报价参数生成 `quote_result`。系统必须先生成初始报价，再由人工调整确认。

## 主责

开发者 A 主责。

## 输入

| 输入 | 说明 |
|---|---|
| `part_feature` | 材料、几何、风险。 |
| `process_route` | 工序路线。 |
| `quantity_result` | 工程量。 |
| `price_rule` | 价格规则。 |
| 报价参数 | 税率、管理费率、取整规则。 |

## 输出

| 输出 | 说明 |
|---|---|
| `quote_result` | 报价结果。 |
| `quote_item` | 报价明细。 |
| `quote_summary` | 汇总。 |
| 风险 | 价格缺失、价格异常、必确认项。 |

## 报价公式

```text
材料费 = 毛重 × 材料单价
加工费 = Σ(工序工程量 × 工序单价，结合起步价、调机费和风险附加)
表面处理费 = Σ(表面处理工程量 × 表面处理单价)
管理费 = 材料费 × 管理费率
税金 = 税金基数 × 税率
系统计算价 = 材料费 + 加工费 + 表面处理费 + 管理费 + 税金
系统初始报价 = 系统计算价按取整规则和报价规则生成的可编辑报价
最终确认价 = 报价员确认或修改后的价格
```

## 报价明细类型

| 类型 | 说明 |
|---|---|
| `material` | 材料费。 |
| `process` | 加工工序费。 |
| `surface_treatment` | 表面处理费。 |
| `management_fee` | 管理费。 |
| `tax` | 税金。 |
| `risk_surcharge` | 风险附加。 |
| `other` | 其他人工补录项。 |

## 报价项必须包含

| 字段 | 说明 |
|---|---|
| `item_id` | 明细 ID。 |
| `item_type` | 明细类型。 |
| `operation_code` | 关联工序，可为空。 |
| `quantity` | 工程量。 |
| `unit` | 单位。 |
| `unit_price` | 单价。 |
| `amount` | 金额。 |
| `price_source` | 价格来源。 |
| `formula` | 计算公式。 |
| `explanation` | 说明。 |

## 状态规则

| 条件 | 报价状态 |
|---|---|
| 无必确认风险 | `priced` |
| 有必确认风险 | `pending_review` |
| 人工确认完成 | `confirmed` |
| 作废 | `voided` |

## 人工修改

人工修改必须通过 `human_override` 保存。

要求：

| 要求 | 说明 |
|---|---|
| 原始值保留 | 系统初始值不得被覆盖。 |
| 原因必填 | 所有修改必须填写原因。 |
| 修改可追踪 | 保存操作人和时间。 |
| 可对比 | 初始报价和最终确认价可对比。 |

## 风险处理

| 风险 | 处理 |
|---|---|
| `MISSING_PRICE` | 可生成初始报价但缺失项必须待确认。 |
| `WEIGHT_MISMATCH` | 状态进入 `pending_review`。 |
| `UNKNOWN_MATERIAL` | 不得使用默认材料价。 |
| `PRICE_OUTLIER` | 提示复核。 |
| `HIGH_PRECISION_REQUIREMENT` | 可添加风险附加或待确认。 |

## 不做什么

- 不解析 PDF 或 STEP。
- 不让 AI 决定价格。
- 不自动确认最终报价。
- 不修改价格规则表。
- 不覆盖系统初始报价。

## 验收标准

- 报价明细可解释率 100%。
- 价格来源可追溯。
- 人工修改记录完整率 100%。
- 有 blocking 风险不得确认。
- `quote_result` 通过 Schema 校验。

## AI Coding 注意事项

- 不要把报价公式散落在前端。
- 不要在价格缺失时生成看似正常的总价。
- 不要用浮点误差影响金额汇总。
- 不要在人工修改后丢失系统初始报价。
