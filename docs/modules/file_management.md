# 文件管理模块

## 模块目标

管理报价任务相关文件，包括 PDF 图纸、STEP 模型和附件。文件管理模块只负责上传、校验、版本、绑定和状态，不负责解析、核价或报价确认。

## 主责

开发者 B 主责，开发者 A 提供任务状态和后续消费接口。

## 输入

| 输入 | 说明 |
|---|---|
| `task_id` | 报价任务 ID。 |
| PDF 文件 | 图纸文件。 |
| STEP 文件 | 三维模型文件，扩展名 `.step` 或 `.stp`。 |
| 附件 | 第一版只保存，不参与自动核价。 |
| 上传人 | 当前用户 ID。 |

## 输出

| 输出 | 说明 |
|---|---|
| `part_file` | 文件记录。 |
| 文件版本 | 同一任务同类文件递增版本。 |
| 文件状态 | `uploaded`、`invalid`、`deleted`。 |
| 文件风险 | 缺 PDF、缺 STEP、格式错误等。 |

## `part_file` 字段建议

| 字段 | 类型 | 要求 |
|---|---|---|
| `file_id` | string | 唯一 ID。 |
| `task_id` | string | 所属任务。 |
| `file_type` | enum | `pdf`、`step`、`attachment`。 |
| `filename` | string | 原始文件名。 |
| `storage_path` | string | 存储位置。 |
| `version` | number | 同类文件版本。 |
| `size_bytes` | number | 文件大小。 |
| `checksum` | string | 文件校验值。 |
| `status` | enum | `uploaded`、`invalid`、`deleted`。 |
| `uploaded_by` | string | 上传人。 |
| `uploaded_at` | string | 上传时间。 |

## 主要规则

| 规则 | 要求 |
|---|---|
| 文件必须绑定任务 | 不允许存在无任务文件。 |
| 支持多版本 | 同一任务可重新上传 PDF 或 STEP，新文件版本递增。 |
| 文件不可物理覆盖 | 新版本不覆盖旧版本。 |
| 删除采用逻辑删除 | 已参与报价的文件不得物理删除。 |
| 附件不参与计算 | 附件只保存和展示。 |
| 缺文件不阻塞初始报价 | 缺 PDF 或 STEP 可继续，但必须生成风险。 |

## 文件校验

| 校验项 | 处理 |
|---|---|
| 扩展名不合法 | 拒绝上传，返回结构化错误。 |
| 文件为空 | 拒绝上传。 |
| 文件过大 | 拒绝上传或提示超限。 |
| 文件重复 | 可提示已存在，但允许作为新版本上传。 |
| PDF/STEP 缺失 | 不拒绝任务，生成 `MISSING_PDF` 或 `MISSING_STEP`。 |

## 异常处理

| 异常 | 系统动作 |
|---|---|
| 存储失败 | 返回错误，不生成有效文件记录。 |
| 文件校验失败 | 生成 `invalid` 记录或直接拒绝，按实现统一。 |
| 上传中断 | 不改变任务状态。 |
| 文件被删除 | 已生成报价的历史数据仍可追溯。 |

## 不做什么

- 不解析 PDF 字段。
- 不解析 STEP 几何。
- 不生成 `part_feature`。
- 不计算工序、工程量和价格。
- 不决定报价状态是否可确认。

## 关联接口

| 接口 | 说明 |
|---|---|
| `POST /api/quote-tasks/{task_id}/files` | 上传文件。 |
| `GET /api/quote-tasks/{task_id}` | 查询任务和文件列表。 |
| `POST /api/quote-tasks/{task_id}/parse` | 触发解析。 |

## 验收标准

- PDF、STEP、附件均可上传。
- 同类文件支持多版本。
- 文件记录可查询。
- 缺 PDF 或缺 STEP 能生成风险。
- 已上传文件可被解析模块消费。

## AI Coding 注意事项

- 不要把文件上传逻辑和解析逻辑混在一个函数里。
- 不要用文件名作为业务唯一标识。
- 不要物理覆盖历史文件。
- 不要在前端自行判断最终报价状态。
